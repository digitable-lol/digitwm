# digitwm

Оконный менеджер для X11 со скроллируемым тайлингом: окна встают колонками на
бесконечной горизонтальной ленте, а экран — это вьюпорт, едущий вдоль неё, так
что новое окно сдвигает ленту, а не ужимает соседей. Двоичный файл и
справочные страницы сохраняют имена cwm — `cwm`, `cwm(1)`, `cwmrc(5)`, — и
грамматика файла настроек тоже cwm'ская; сам файл наш,
`~/.digitable/digitwm/digitwmrc`, а cwm'ский `~/.cwmrc` по-прежнему читается —
для тех, кто пришёл из cwm.

**English: [README.md](README.md).**

## Сборка

Компилятор C, `make` (BSD или GNU), `yacc` или `bison`, `pkg-config` и
заголовки `x11`, `xft` и `xrandr`. Это весь список: ничто из `fts/` не является
зависимостью рантайма, поэтому Node.js не нужен ни для сборки, ни для запуска.
Компилятора flang в списке тоже нет, хотя арифметика ленты написана на flang:
она напечатана в C заранее, и напечатанное лежит в дереве —
`ribbon-flang/out-c/`. Довод и цена — в
[ribbon-flang/README.md](ribbon-flang/README.md).

```sh
make
make install PREFIX=$HOME/.local   # bin/cwm, share/man/man1/cwm.1, share/man/man5/cwmrc.5
```

`PREFIX`, `DESTDIR` и `MANPREFIX` учитываются. Имена пакетов по системам и путь
одной командой, который ставит ещё и зависимости с окружением (`sh
bootstrap.sh`, сначала `sh bootstrap.sh --plan`), — в
[doc/build.ru.md](doc/build.ru.md).

## Запуск

```sh
exec cwm                 # только оконный менеджер
exec digitwm-session     # он же плюс окружение, которое раскладывает session/install.sh
```

`session/install.sh` кладёт ещё и `digitwm.desktop` в
`~/.local/share/xsessions` (с `--system` — в `/usr/share/xsessions`), поэтому
менеджер входа предлагает сессию по имени.

## Настройка

Сессия запускает `cwm -c ~/.config/digitwm/cwmrc`; запущенный сам по себе `cwm`
берёт первый существующий файл из `$DIGITWMRC`,
`~/.digitable/digitwm/digitwmrc` и cwm'ского `~/.cwmrc` — и если это последний,
говорит об этом один раз в stderr. `cwm -n` печатает выбранный файл и
останавливается. Все настройки описаны в `cwmrc(5)`; настройки, привязки
клавиш и команды самой ленты — в [doc/ribbon.ru.md](doc/ribbon.ru.md) и
[doc/commands.ru.md](doc/commands.ru.md). Конфигурация, написанная для
апстримного cwm, переносится без правок; конфигурацию со старыми именами команд
прогоняют через апстримный `migrate-config.pl`:
`perl migrate-config.pl <старый >новый`.

## Проверка правки

Дисплей X для этого не нужен, и проверяется то дерево, которое вы только что
собрали:

```sh
make
sh tools/no-x-build.sh                          # ribbon.c собирается без Xlib, шов — wsi.h
sh tools/check-ribbon-flang.sh                  # лента отвечает как до flang: 526871 вход, побайтно
node fts/harness/invariants.mjs --wm ./cwm      # два обещания, на собранном двоичном файле
node fts/harness/hotplug.mjs    --wm ./cwm      # монитор уходит и возвращается
python3 tools/check-licensing.py                # лицензионный шлюз, его CI гоняет на каждый push
./cwm -C 'layout-probe layout viewport=1280x800 gap=8 border=1 columns=1,3,1 presets=0,2,3 focus=1'
```

Последняя строка — это раскладка, отвечающая за себя сама: тот же вызов, каким
пользуется харнесс конформанса, и способ увидеть, что правка сделала с
раскладкой, не поднимая сессии. `make macos-check` проверяет переносимую
половину слоя macOS, и мака для этого не нужно.

Остальное, что гоняет CI, — `surfaces.mjs`, `conformance.mjs`, `selftest.mjs` и
сами модели из `fts/` — требует инструментария FTS, который клонируется по тегу
из репозитория языка. Эти команды есть в [doc/build.ru.md](doc/build.ru.md), а
`.github/workflows/fts-conformance.yml` выполняет их в том же порядке. Порядок,
в котором вносится правка в раскладку, — в
[CONTRIBUTING.ru.md](CONTRIBUTING.ru.md): модель первой, C — четвёртым.

## Дерево

| | |
|---|---|
| `ribbon.c` | лента: колонки, стопки, вьюпорт, вставка, фокус. X11 в ней не назван — одиннадцать операций, которые она просит у оконной системы, объявлены в `wsi.h`. Десять скалярных политик в ней — обёртки: сама арифметика приезжает из `ribbon-flang/` |
| `ribbon-flang/` | арифметика ленты на flang: подмодуль [flang-ribbon](https://github.com/digitable-lol/flang-ribbon) на закреплённом отпечатке и напечатанный из него C. `out-c/` — вывод компилятора под контролем версий, и его README объясняет зачем |
| `probe.c` | `layout-probe`: раскладка отвечает, не открывая дисплея |
| `calmwm.c`, `client.c`, `screen.c`, `xevents.c`, `group.c`, `kbfunc.c`, `menu.c`, `search.c` | от cwm: клиенты, экраны, события, группы, привязки клавиш, меню |
| `conf.c`, `parse.y` | умолчания и разбор файла настроек |
| `confpath.c` | какой файл настроек читается и в каком порядке перебираются кандидаты — один файл на обе сборки, X11 и macOS |
| `fts/` | модели раскладки и харнессы над ними. Работают в CI, внутри оконного менеджера — никогда |
| `doc/` | документы, каждый на двух языках |
| `session/` | окружение вокруг оконного менеджера и его установщик |
| `tools/` | скрипты измерений и клиенты-пробы, которыми они пользуются |
| `pkgsrc/`, `macos/` | пакет pkgsrc; проверяемая половина слоя macOS |

## Состояние

Раннее. Лента есть и проверена харнессами — колонки, стопки, едущий вьюпорт,
вставка, фокус, пресеты ширины, своя лента на каждый выход, — но в ней никто не
прожил неделю, панель проверена на одном мониторе и без батареи
([doc/panel.ru.md](doc/panel.ru.md)), а пути поставки (`bootstrap.sh`, порт
pkgsrc) прогнаны на Debian и вычитаны глазами, а не проверены на каждой
системе, которую они называют. В каждом документе сказано, что в нём измерено,
а что нет.

Лицензия: наши файлы — под **BSD-2-Clause**, дословный текст в
[LICENSE](LICENSE). Унаследованные от
[cwm](https://github.com/leahneukirchen/cwm) остаются под **ISC**, их
уведомление со всеми правообладателями — в
[LICENSE.upstream](LICENSE.upstream); `queue.h` один под BSD-3-Clause. Что к
чему относится и почему лицензия сменилась — в [NOTICE](NOTICE) и
[LICENSE-RU.md](LICENSE-RU.md). Шапки апстрима не трогаются, наши файлы несут
свою, и разделяет эти два множества `tools/check-licensing.py`. Часть [Digitable](https://digitable.life); разбор с
числами прогонов — на
[courses.digitable.life/digitwm](https://courses.digitable.life/digitwm/), там
же сказано, почему digitwm не входит в платный архив Workbench, хотя лицензия
этого не запрещает.
