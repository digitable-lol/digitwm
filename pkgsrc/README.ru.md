# Порт для pkgsrc

**English version: [README.md](README.md).**

`wm/digitwm` — пакет pkgsrc для одного только оконного менеджера: без сессии,
без тем, без агента. Лежит он здесь, а не в pkgsrc, потому что ещё не подан
туда; скопируйте и соберите:

```sh
cp -r pkgsrc/wm/digitwm /usr/pkgsrc/wm/digitwm
cd /usr/pkgsrc/wm/digitwm
make makesum          # запишет distinfo по релизному архиву
make install
```

## Почему нет `distinfo`

В `distinfo` лежат контрольные суммы дистрибутивного файла. **Релизного архива
пока нет** — тег не выложен, — значит, считать сумму не с чего, а выдуманный
хеш был бы хуже отсутствующего файла: он свалил бы сборку на этапе загрузки с
сообщением о порче архива вместо сообщения об отсутствующем релизе. `make
makesum` создаёт его одной командой, как только появится `v0.1.0`.

По той же причине в `DISTNAME` стоит `0.1.0`, а в `GITHUB_TAG` —
`v${PKGVERSION_NOREV}`: это версия, которую понесёт первый релиз, а не уже
опубликованная.

## Что проверено, а что нет

**Проверено:** пакет не собирает ничего необычного. Makefile в корне
репозитория — переносимый между BSD- и GNU-make, спрашивает три библиотеки X
через `pkg-config`, а разбор конфигурации собирает `yacc`, уважает `PREFIX`,
`DESTDIR` и `MANPREFIX` и ставит ровно те три файла, которые перечислены в
`PLIST`. `make install PREFIX=…` в пустой каталог прогнан и дал `bin/cwm`,
`share/man/man1/cwm.1` и `share/man/man5/cwmrc.5`.

**Не проверено:** сам порт средствами pkgsrc не собирался. Ни дерева pkgsrc,
ни машины с NetBSD здесь нет; `bmake`, `pkgin` и `pkglint` отсутствуют.
Написанное в порте верно по построению и по руководству, а не потому, что
прогон был зелёным. Не считайте порт проверенным, пока кто-нибудь не прогонит
на нём `pkglint` и `make install`.

## Имя двоичного файла

Двоичный файл по-прежнему называется **`cwm`**, и страницы руководства тоже —
чтобы `cwmrc` и всё написанное про cwm переносилось без правок. Поэтому в
пакете стоит `CONFLICTS+= cwm-[0-9]*`: рядом эти два пакета не встанут.

Переименовывать ли форку свой двоичный файл — решение с ценой по обе стороны:
переименование ломает всякий конфигурационный файл, сессионный скрипт и
`.xinitrc`, где уже написано `cwm`; сохранение имени мешает поставить оба
пакета вместе. Это решение владельца, а не порта.

## Не оконный менеджер, а всё окружение

Порт ставит оконный менеджер и больше ничего. Окружение, ради которого он
задуман — редактор, терминал, оболочка, мультиплексор, темы Digitable Focus и
агент Digit, — ставит [`bootstrap.sh`](../bootstrap.sh) в корне репозитория, и
он же и есть та «одна команда» из `DGT-WM-12`:

```sh
sh bootstrap.sh --plan     # посмотреть, что будет сделано
sh bootstrap.sh            # сделать
session/verify.sh          # проверить, что получилось
```

Разделение намеренное. Пакетный менеджер ставит программы, а сессия
раскладывает конфигурацию в домашнем каталоге пользователя, и делать это из
post-install пакета она не вправе.
